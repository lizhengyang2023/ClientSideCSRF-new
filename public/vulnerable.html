⚠️ 有漏洞的受害者页面 - CS-CSRF演示

此页面包含客户端请求伪造漏洞，即使服务器有CSRF Token保护也能被绕过

⚠️ 警告 本页面仅用于教育目的，展示CS-CSRF漏洞。即使服务器使用了CSRF Token保护， 客户端代码的漏洞仍然可以被利用。

🔍 漏洞分析

漏洞类型：Client-Side Request Forgery (CS-CSRF)

漏洞原理：

  • Source（漏洞源头）：window.location.search - 不受信任的URL参数
  • Propagator（数据传播）：URL参数被直接复制到请求Body
  • Sink（漏洞汇点）：fetch()函数使用动态构建的URL和参数
  • Authentication（认证混淆）：客户端代码自动读取并添加CSRF Token
// 【漏洞代码】根据URL参数动态调用API
const params = new URLSearchParams(window.location.search);
if (params.has('action')) {
const action = params.get('action');
const payload = {};
for (const [key, value] of params) {
if (key !== 'action') {
payload[key] = value;
}
}
// 自动读取CSRF Token（混淆代理）
const token = document.querySelector('meta[name="csrf-token"]').content;
fetch(`/api/csrf-protected/${action}`, {
method: 'POST',
headers: {
'Content-Type': 'application/json',
'CSRF-Token': token // Token被自动添加！
},
body: JSON.stringify(payload)
});
}

📋 攻击流程说明

  1. 攻击者构造恶意URL：http://127.0.0.1:3000/vulnerable.html?action=transfer&to=attacker@evil.com&amount=1000
  2. 用户点击链接，浏览器加载页面
  3. 服务器生成合法的CSRF Token并嵌入HTML
  4. 客户端JS解析URL参数，提取action和payload
  5. 客户端JS自动读取CSRF Token
  6. 客户端JS发送POST请求，Token被自动添加到请求头
  7. 服务器验证Token（合法！），请求成功执行
  8. 攻击完成，CSRF保护被绕过！

等待操作...如果URL中包含action参数，页面加载时会自动执行。
