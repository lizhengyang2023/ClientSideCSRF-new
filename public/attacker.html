11CS-CSRF攻击：绕过CSRF Token保护 Client-Side CSRF

攻击原理：这是最危险的攻击之一！即使服务器使用了CSRF Token保护，客户端代码的漏洞仍然可以被利用。 客户端代码根据URL参数动态调用API，并自动读取并添加CSRF Token，导致攻击者可以通过构造URL来绕过Token保护。 这是"混淆代理"攻击：客户端代码成为了攻击者的帮凶。

⚠️ 关键特征：
• Source（漏洞源头）：window.location.search - 不受信任的URL参数
• Propagator（数据传播）：URL参数被直接复制到请求Body
• Sink（漏洞汇点）：fetch()函数使用动态构建的URL和参数
• Authentication（认证混淆）：客户端代码自动读取并添加CSRF Token

// 攻击者构造恶意URL，诱导用户点击： // http://127.0.0.1:3000/vulnerable.html?action=transfer&to=attacker@evil.com&amount=1000

// 受害者页面的漏洞代码：
document.addEventListener('DOMContentLoaded', () => {
const params = new URLSearchParams(window.location.search);

if (params.has('action')) {
const action = params.get('action'); // 从URL参数获取

// 【漏洞】所有URL参数都被复制到payload
const payload = {};
for (const [key, value] of params) {
if (key !== 'action') {
payload[key] = value; // 攻击者可控！
}
}

// 【混淆代理】客户端自动读取并添加CSRF Token
const token = document.querySelector('meta[name="csrf-token"]').content;

// 【攻击成功】请求被发送，Token被自动添加
fetch(\`/api/csrf-protected/\${action}\`, {
method: 'POST',
headers: {
'Content-Type': 'application/json',
'CSRF-Token': token // Token自动添加，绕过保护！
},
body: JSON.stringify(payload)
});
}
});

🔍 CS-CSRF攻击详细分析

攻击流程（8步）：

  1. 攻击者构造恶意URL：
    http://127.0.0.1:3000/vulnerable.html?action=transfer&to=attacker@evil.com&amount=1000
  2. 用户点击链接：用户通过邮件、消息等方式访问恶意URL
  3. 浏览器加载页面：浏览器向受害者服务器请求页面
  4. 服务器生成CSRF Token：服务器生成合法的Token并嵌入HTML的meta标签
  5. 客户端JS解析URL参数：脚本提取action和payload参数
  6. 客户端JS自动读取Token：脚本从meta标签读取CSRF Token
  7. 客户端JS发送POST请求：请求包含Token和攻击者控制的参数
  8. 服务器验证成功：Token合法，请求执行，攻击成功！

为什么CSRF Token保护失效？

  • Token是合法的（由服务器生成）
  • Token由客户端代码自动添加（"混淆代理"）
  • 攻击者无需知道Token值，只需控制URL参数
  • 客户端代码成为了攻击者的帮凶

与Facebook漏洞的相似性：

2019年Facebook的CS-CSRF漏洞与本演示非常相似：
• Facebook的客户端JS自动附加fb_dtsg Token
• 攻击者通过URL参数控制请求的目标和内容
• Token保护被成功绕过

防御方法：

  • 白名单机制：不要直接将URL参数作为API端点，使用映射表
  • 分离HTTP方法：GET请求不应触发状态改变
  • Token作用域限制：为不同操作生成不同的Token
  • 输入验证：验证所有用户输入，不仅仅是URL参数
